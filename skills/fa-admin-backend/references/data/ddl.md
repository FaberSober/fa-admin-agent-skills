# DDL 参考

## 数据库类型与基线

编写或修改 SQL 前，必须先确定目标数据库类型，不允许写“同时兼容两种数据库”的混合方言脚本。

| 数据库类型目录 | 数据库基线 | 用途 |
| --- | --- | --- |
| `mysql` | `fa-base/src/main/resources/sql/fa-base/mysql/1.0.0_base_ddl.sql` | MySQL（兼容现有 MySQL 5.7 语法） |
| `postgre` | `fa-base/src/main/resources/sql/fa-base/postgre/1.0.0_base_ddl.sql` | PostgreSQL 18 |

模块 SQL 固定位置为 `src/main/resources/sql/{模块编码}/{mysql|postgre}/{版本}*.sql`。升级组件按 JDBC 产品名自动选择对应目录；禁止回退到另一种数据库脚本。

MySQL 建表优先采用：

```sql
CREATE TABLE IF NOT EXISTS `table_name` (
  ...
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='中文表注释';
```

PostgreSQL 建表优先采用：

```sql
CREATE TABLE IF NOT EXISTS "table_name" (
  "id" bigint GENERATED BY DEFAULT AS IDENTITY NOT NULL,
  ...,
  PRIMARY KEY ("id")
);
COMMENT ON TABLE "table_name" IS '中文表注释';
```

维护已有 `utf8` 老表时，除非任务明确要求字符集迁移，否则保留现有风格，不主动统一改造。

## 数据库初始化与主键策略

版本 SQL 由框架自动初始化执行，入口是 `com.faber.api.base.admin.biz.SystemUpdateLogBiz.initDb()`，按版本升序跑模块 `sql/{类型}/{版本}*.sql`。每个模块如何登记自己的版本 SQL，参考 `com.faber.api.base.demo.FaDemoDbInit`。

主键选型直接影响前后端契约：

- 选 `bigint` + 自增主键时，Java 侧是 `Long`，框架默认把 Long 序列化为字符串返回前端，前端 TS 也按 `string` 承接；将来要换成 UUID，只需把后端字段改 `String`、ID 生成逻辑改 UUID，前端 `string` 类型不动。
- 选 `int`/`int unsigned` 自增主键时，Java 侧是 `Integer`，多见于配置、字典、菜单、角色、日志等低并发系统表。
- 选 `varchar(32)` 主键时多见于用户、部门、文件、租户等表，通常用 UUID/雪花字符串。
- 不要为了"统一"把所有新表主键都改成同一类型；关联外键列必须与被引用表真实主键类型一致。

整型宽度按需选：`bigint` 8 字节、`int` 4 字节、`smallint` 2 字节、`tinyint` 1 字节；枚举/标志位常用 `tinyint`。

## 审计字段与字段类型

普通业务表继承 `BaseDelEntity`，审计列由 MyBatis-Plus `FieldFill` 自动填充（crt_* 在 INSERT、upd_* 在 UPDATE），两库仅标识符和布尔类型不同：

MySQL：

```sql
`crt_time` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
`crt_user` varchar(32) NOT NULL COMMENT '创建用户ID',
`crt_name` varchar(255) NOT NULL COMMENT '创建用户',
`crt_host` varchar(255) DEFAULT NULL COMMENT '创建IP',
`upd_time` timestamp NULL DEFAULT NULL COMMENT '更新时间',
`upd_user` varchar(32) DEFAULT NULL COMMENT '更新用户ID',
`upd_name` varchar(255) DEFAULT NULL COMMENT '更新用户',
`upd_host` varchar(255) DEFAULT NULL COMMENT '更新IP',
`deleted` tinyint(1) NOT NULL DEFAULT '0' COMMENT '是否删除',
```

日志表、纯关联日志、系统升级记录等表，如果相邻先例只保留部分审计字段，可以保持一致。逻辑删除字段统一使用 `deleted`，不要改成 `is_deleted` 或 `del_flag`。

PostgreSQL：

```sql
"crt_time" timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
"crt_user" varchar(32) NOT NULL,
"crt_name" varchar(255) NOT NULL,
"crt_host" varchar(255) DEFAULT NULL,
"upd_time" timestamp NULL DEFAULT CURRENT_TIMESTAMP,
"upd_user" varchar(32) DEFAULT NULL,
"upd_name" varchar(255) DEFAULT NULL,
"upd_host" varchar(255) DEFAULT NULL,
"deleted" boolean NOT NULL DEFAULT false,
```

审计列由 MyBatis-Plus `FieldFill` 在 INSERT/UPDATE 时自动填充，两库都不要写 `ON UPDATE CURRENT_TIMESTAMP`，也不要建触发器。逻辑删除列统一 `deleted`，Java 侧是 `Boolean`（`@TableLogic`），不改成 `is_deleted`/`del_flag`。

Java Entity 类型必须与目标 DDL 对齐：

| Java Entity 类型 | MySQL | PostgreSQL |
| --- | --- | --- |
| `Boolean` / `boolean` | `tinyint(1)`，使用 `0/1` | `boolean`，使用 `true/false` |
| `Integer` | `int(11)` 或相邻表的更小数值类型 | `integer` 或相邻表的 `smallint` |
| `Long` | `bigint` | `bigint` |
| `String` | `varchar` / `text` | `varchar` / `text` |
| JSON 字符串/JSON 类型处理器 | `json` | `jsonb` |
| `Date` | `timestamp` / `datetime` | `timestamp` |

PostgreSQL 不能以 `smallint` 存储 Java `Boolean`；否则查询或写入布尔参数会产生类型运算错误。

## 主键与字段类型

不要把所有新表主键统一成 `BIGINT`。

- 配置、字典、菜单、角色、日志类表常见 `int(11)` 或 `int(11) unsigned AUTO_INCREMENT`。
- 用户、部门、文件等表常见 `varchar(32)`。
- 部分历史基础表可能使用 `mediumint` 或 `bigint unsigned`。
- 类外键字段应匹配被关联表的真实主键类型。

默认不添加数据库外键约束，优先通过业务约束和索引控制关联关系。

## 命名与索引

优先复用已有字段名，例如 `status`、`sort`、`sort_id`、`description`、`remark`、`parent_id`、`user_id`、`xxx_user`。MySQL 布尔语义字段使用 `tinyint(1)` 并注明 `0/1` 含义；PostgreSQL 使用 `boolean` 并注明 `true/false` 含义。

每张表至少包含主键。唯一索引、普通索引按业务唯一性和查询条件决定，不要为了“规范化”给每个字段都建索引。索引名保持简洁，并与相邻脚本兼容；相邻脚本使用 `USING BTREE` 时继续保留该风格。

## 版本脚本安全与幂等性

- 文件名版本、`@@ver`、`@@info` 必须一致；不要重用或倒退版本号。
- 已发布版本脚本不可修改；空库基线测试期的修正必须由用户明确授权。
- 禁止 `DROP TABLE`、`DROP SCHEMA`、`TRUNCATE`；升级执行器会拒绝这些语句。
- MySQL 与 PostgreSQL 的同一业务版本应保持对象与语义等价，但脚本语法必须各自合法。
- 新表使用 `CREATE TABLE IF NOT EXISTS`；PostgreSQL 新增列优先 `ADD COLUMN IF NOT EXISTS`，避免空库完整版本链与初始基线重复列失败。
- 不要通过删除/重建表来修正字段类型或结构；生产迁移必须采用安全的增量变更方案。

## 菜单 SQL

菜单段位表见 [menu.md](menu.md)。菜单 INSERT 的字段顺序和方言规则：

默认字段顺序：`id, parent_id, name, sort, level, icon, status, link_type, link_url, crt_time, crt_user, crt_name, crt_host, upd_time, upd_user, upd_name, upd_host, deleted`。

- MySQL 用反引号、`status`/`deleted` 用 `1`/`0`。
- PostgreSQL 用双引号、`status`/`deleted` 用 `true`/`false`，推荐 `ON CONFLICT (id) DO NOTHING`。
- `link_url` 与前端页面目录一致。
